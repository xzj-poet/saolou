# 代理临时密码与强制改密设计

**日期：** 2026-10-09
**状态：** 已完成本地实现与自动化验证，待用户最终验收

## 目标

代理不必长期记忆管理员生成的随机临时密码：首次使用临时密码登录后，自行设置一个至少 6 位、无字符类型限制的新密码。此后只使用新密码登录。

管理员保留重置密码能力。重置会产生新的临时密码、立即让旧密码与既有会话失效，并让代理下一次登录后再次强制改密。

## 已确认的产品规则

- 仅 `AGENT` 代理账号参与此流程；管理员账号不受影响。
- 新建代理会获得临时密码，并在首次登录后强制改密。
- 管理员重置代理密码后，同样强制改密。
- 代理新密码最少 6 位；不要求数字、符号或大小写等额外组合规则。
- 设置新密码时必须重复输入确认，防止输入错误。
- 强制改密前，代理不能访问任何业务页面。

## 数据模型

在 `User` 增加布尔字段：

```prisma
mustChangePassword Boolean @default(false) @map("must_change_password")
```

- 创建代理时写入 `true`。
- 管理员重置代理密码时写入 `true`。
- 代理成功更新自己的密码时写入 `false`。
- 现有账号的迁移默认值为 `false`，不强制打断当前已经正常使用的账号；管理员可按需重置某位代理，使其进入新流程。

## 登录与访问控制

1. 登录接口继续验证账号、密码与账号状态，并创建正常会话。
2. 会话解析结果携带 `mustChangePassword`，让服务端可以在每次受保护页面访问时作出判断。
3. `AGENT` 且 `mustChangePassword=true` 的会话，只允许访问“设置新密码”页面；直接访问学校、楼栋、宿舍、批量录入等任意业务路径都会被服务端重定向。
4. 设置密码成功后，该标志清除，代理无需重新登录即可进入代理端。
5. 设置密码页提供退出登录入口，便于临时密码或账号拿错时安全退出。

此处的限制由服务端布局和 API 身份校验共同执行，不能通过刷新页面、修改网址或绕过前端按钮逃避。

## API 与密码处理

新增受认证的改密接口，例如 `POST /api/auth/change-password`：

- 仅允许当前登录的 `AGENT` 使用；管理员请求返回权限错误。
- 采用现有同源校验与统一 API 错误格式。
- 请求包含 `newPassword` 和 `confirmPassword`；两者必须相同，且新密码长度为 6–128 位。
- 会话本身已经证明代理刚刚通过临时密码认证，因此首次设置新密码不重复索取临时密码。
- 密码仍使用现有 scrypt 哈希保存，绝不保存或返回代理自行设置的新密码明文。
- 现有密码哈希工具的最小长度校验从 10 位同步调整为 6 位，确保新建、重置与代理自主改密使用相同规则。

## 管理员重置流程

现有管理员重置接口继续生成并只返回一次临时密码，同时在一个数据库事务内：

1. 写入新密码哈希；
2. 将 `mustChangePassword` 设为 `true`；
3. 删除该代理所有既有会话。

管理员界面将结果明确称为“临时密码”，并提示“代理登录后必须自行设置新密码”。管理员负责通过合适的内部渠道把临时密码交给代理；系统不持久保存或二次展示其明文。

## 页面与导航

- 新增独立的设置新密码页面，显示账号名、两次密码输入框、保存按钮、校验错误提示与退出登录入口。
- 该页面不显示业务导航，防止产生“已经可访问系统”的误解。
- 正常代理端和管理员端沿用现有导航与权限逻辑。

## 验证与验收

将新增或更新自动化测试，覆盖：

- 新建代理初始状态为“需改密”。
- 临时密码登录成功后，服务端阻止访问业务页面。
- 两次密码不一致、少于 6 位、非代理调用等失败情况。
- 成功改密后标志清除，旧临时密码不能再次登录，新密码可登录。
- 管理员重置后旧会话失效，并再次进入强制改密流程。
- 管理员不受代理改密页面和接口限制。
