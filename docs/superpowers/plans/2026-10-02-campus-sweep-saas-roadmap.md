# 校园扫楼 SaaS 实施路线图

> 本路线图把已经冻结的 v31 原型拆成五个可以独立验收的实施阶段。每个阶段开始前再写对应的详细实施计划，不跨阶段预写大量容易失效的代码级步骤。

**目标：** 将 `docs/prototype/campus-sweep-saas-prototype.html` 转化为一个只服务单团队、在线使用、可部署和可审计的真实 Web SaaS。

**架构：** 使用 Next.js 模块化单体承载响应式页面与 JSON 接口，PostgreSQL 作为唯一业务真相，Prisma 7 负责数据库访问和事务。权限、状态聚合、唯一当前记录与审计均在服务端执行；原型只作为界面和交互验收依据，不作为生产代码直接移植。

**技术基线：** Node.js 24 LTS、Next.js 16.3.8、TypeScript 5.9、Prisma 7、PostgreSQL 18、Zod、Playwright、Docker Compose、Caddy。

**产品设计：** `docs/superpowers/specs/2026-09-29-campus-sweep-saas-design.md`

## 阶段 1：工程基础、数据库与身份会话

交付：

- 可启动、可测试、可构建的 Next.js 应用。
- 完整的第一版数据库模型和初始迁移。
- 管理员种子账号。
- 登录、退出、会话校验、角色跳转与服务端路由保护。
- 代理端和管理员端的受保护页面壳层。
- 本地 PostgreSQL 开发环境和自动化质量门。

验收门槛：

- 管理员与代理使用同一入口登录，分别到达正确首页。
- 错误凭据不泄露账号是否存在；禁用账号收到专用提示。
- 会话 Cookie 不包含用户与权限声明，退出后立即失效。
- 未登录用户无法访问受保护页面或接口。
- lint、类型检查、单元测试、数据库集成测试和生产构建全部通过。

详细计划：`docs/superpowers/plans/2026-10-02-campus-sweep-saas-foundation-auth.md`

## 阶段 2：学校、楼栋、宿舍与代理学校权限

交付：

- 管理员学校收纳栏、楼栋卡片、宿舍蓝图和宿舍管理弹窗。
- 学校、楼栋、宿舍的添加、编辑、停用、恢复与受保护删除。
- 批量生成宿舍与重复项预览。
- 楼层数、宿舍数完全由有效宿舍派生。
- 代理账号创建、改名、启停、重置密码和学校授权。
- 代理学校选择页与楼栋选择页。

验收门槛：

- 只建立 201、202 时，两端均显示“1层 · 2间宿舍”。
- 楼栋备注中的数字不影响统计。
- 有下级数据或扫楼记录时只能停用，不能级联删除。
- 取消授权后旧链接立即返回 403，但历史数据不丢失。

## 阶段 3：扫楼记录核心与代理主流程

交付：

- 楼栋矩阵、整体状态聚合和“我扫过”星号。
- 单间新增、编辑和批量标记共用统一记录编辑器。
- `代理 × 宿舍` 唯一当前记录。
- 单条和整批原子 upsert。
- 宿舍详情、各代理最新状态历史页和完整返回逻辑。
- 保存中、成功、失败重试、放弃修改和加载状态。

验收门槛：

- 一层 20 间宿舍可在两轮批量操作内完成记录。
- 批量保存只能全部成功或全部失败。
- 已覆盖优先于待补扫，待补扫优先于未扫。
- 代理不能通过修改请求参数写入他人记录。
- 保存后默认返回原楼层矩阵并刷新统计。

## 阶段 4：快捷备注与管理员扫楼数据

交付：

- 快捷备注分组、增删改、排序与启停。
- 代理端最多展示五条的横幅式快捷备注下拉框。
- 当前记录筛选、管理员纠错和删除错误记录。
- 不可变审计日志。
- 快捷备注和删除记录的文字快照。

验收门槛：

- 修改或删除快捷备注不改变旧扫楼记录文本。
- 业务写入和审计写入处于同一事务。
- 无语义变化不更新时间、不新增审计。
- 管理员删除当前记录后，删除前快照仍可永久追溯。

## 阶段 5：可靠性、安全与生产部署

交付：

- 请求速率限制、CSRF 防护、安全响应头和结构化日志。
- 全部关键路径 Playwright 测试和移动端点击尺寸测试。
- Docker 生产镜像、PostgreSQL、Caddy、健康检查和迁移流程。
- 异机每日备份、保留策略和恢复演练脚本。
- 部署与故障恢复手册。

验收门槛：

- 生产构建与容器健康检查通过。
- HTTPS、Cookie 安全属性和数据库最小权限经过验证。
- 登录、矩阵读取、单条保存、批量保存和管理员纠错冒烟测试通过。
- 实际从备份恢复到临时数据库并完成数据核对。

## 跨阶段约束

- 不实现多团队、多租户、计费、代理自助注册、离线同步、销售数据或经营报表。
- 所有权限都由服务端判断；界面隐藏不作为安全边界。
- 每个阶段使用测试驱动开发，先观察失败测试，再写最小实现。
- 每个阶段通过自身验收门槛并由用户确认后，才进入下一阶段。
- 原型继续保留为验收参照，真实应用代码不继续堆入单文件原型。
